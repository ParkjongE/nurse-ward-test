# 간호학생과 신규 간호사를 위한 병동 취향 테스트 PRD

버전 1.0 · 작성일 2026년 9월 25일 · Claude Code 구현용

## 한 페이지 기획 요약

**서비스 이름은 나의 첫 병동.** 간호학생과 신규 간호사가 12개의 일상 및 실습 상상 질문에 답하고, 자신의 선택과 연결된 간호 부서 캐릭터를 발견하는 모바일 중심의 재미용 성향 테스트다. 첫 화면의 카피는 **“나는 어떤 병동과 잘 맞을까?”**, 보조 문구는 **“12개의 선택으로 만나는 나의 간호 스타일”**로 한다. 약 3분은 초기 설계 목표이며 실제 사용 시간은 시범 테스트 후 조정한다.

**핵심 경험.** 크게 등장한 간호사 캐릭터 → 선택형 닉네임 입력 → 한 화면에 한 문항씩 12문항 → 캐릭터 명찰 공개 → “○○님은 이런 선택을 해서 이 유형이 나왔어요” → 병동 설명과 실제 답변에 기반한 이유 → 결과 이미지 저장과 친구에게 공유. 하나의 웹앱 안에서 단계가 바뀌는 SPA이며, 12문항을 긴 페이지에 한꺼번에 나열하지 않는다.

**결과는 7종.** 응급실의 우선순위 나침반, 중환자실의 변화 탐정, 수술실의 준비 지휘자, 내과계 병동의 연결 코디네이터, 소아병동의 눈높이 통역가, 정신건강의학과 병동의 대화 동행자, 종양병동의 여정 메이트. 응급실과 수술실은 엄밀히 병동과 다른 부서이므로 본문에서는 “병동·부서”라고 부른다. 성격에 따른 실제 배치의 정답을 주장하지 않는다.

**결과의 차별점.** 모든 사람에게 같은 칭찬을 보여주지 않는다. 선택한 답변 중 해당 결과에 기여한 2~3개를 제시하고, 선택 → 드러난 취향 → 해당 부서의 업무와 연결되는 지점을 설명한다. “맞을 확률 98%” 대신 “이번 답변에서 가장 가까웠던 유형”을 사용한다. 1위와 2위가 가까우면 두 가지 취향이 함께 나타났다고 알려준다.

**비주얼.** 크림색 배경, 민트 스크럽을 입은 2.5등신 오리지널 간호사 캐릭터, 진한 청록색 버튼, 라운드 명찰과 작은 의료 소품. 병원 안내 사이트보다 캐릭터 굿즈와 그림책 같은 분위기. 첫 화면 캐릭터는 모바일 너비의 약 60~70%를 차지하고, 흐릿한 병원 창문과 커튼은 배경으로만 사용한다. 질문은 클립보드 카드, 결과는 큰 간호사 명찰 카드로 디자인한다.

**모바일 우선.** 360~430px에서 우선 설계하고 320px까지 대응한다. 큰 답변 버튼, 이전/다음 이동, 새로고침 복구, iPhone 안전영역, 확대 시 줄바꿈을 제공한다. PC에서는 중앙 앱 영역과 옆의 캐릭터 일러스트를 배치한다. 결과 설명은 세로 스크롤로 읽되 핵심 결과와 이유는 기본 펼침이다.

**MVP 범위.** 로그인·서버·AI 호출 없이 로컬 규칙 채점, 12문항, 7결과, 닉네임, 결과 근거, 부서 설명, 다시하기, PNG 저장, 링크 공유를 구현한다. MBTI 판정, 의료 지식 시험, 실제 배치 추천, 순위·희귀도, 커뮤니티, 광고는 제외한다. 문항·가중치·결과 카피는 아래 명세를 그대로 데이터로 분리한다.

**완료 기준.** 7개 결과가 모두 도달 가능하고 같은 답변은 항상 같은 결과를 만든다. 결과의 이유는 실제 선택에만 근거한다. 모바일에서 가로 넘침과 버튼 가림이 없고 공유 미지원 환경에 대안이 있다. 임상 업무 설명은 출처를 연결하고, 성향 연결과 가중치는 제작자가 설계한 재미용 규칙임을 명시한다.

## 구현 부록 사용법

위는 한 페이지 수준의 기획 요약이다. 아래는 구현자가 질문이나 결과를 임의로 생략하지 않도록 제공하는 상세 명세다. 이 파일 전체를 Claude Code에 전달한다. 요청 범위는 이 PRD 작성이며, 실제 사이트 구현이나 배포가 완료되었다는 의미는 아니다.

## 2 화면 구성과 정확한 문구

### 시작 화면

- 좌상단 작은 서비스명: “나의 첫 병동”
- 라벨: “간호학생 · 신규 간호사를 위한 취향 테스트”
- 제목: “나는 어떤 병동과\n잘 맞을까?”
- 설명: “실습 전에도, 첫 출근 전에도.\n12개의 선택으로 나의 간호 스타일을 만나보세요.”
- 히어로: 민트 스크럽, 명찰, 펜 2개와 클립보드를 든 중성적인 성인 간호사 캐릭터. 정면 3/4 포즈, 부드러운 웃음. 캐릭터 말풍선 “정답은 없어요. 더 끌리는 쪽을 골라주세요!”
- 이름 입력 라벨: “어떻게 불러드릴까요? (선택)” / placeholder “별명으로 입력해도 좋아요”
- 시작 CTA: “내 병동 취향 알아보기”
- 하단 안내: “12문항 · 약 3분 · 로그인 없이”
- 작은 설명: “재미로 보는 취향 테스트예요. 실제 적성이나 병동 배치를 판단하는 검사는 아니에요.”
- 푸터 링크: “테스트 소개”, “참고 자료”, “내 기록 지우기”

닉네임은 공백 제거 후 1~12개 사용자 인식 문자로 제한한다. 비어 있으면 “예비 간호사”를 사용한다. 제어 문자와 줄바꿈은 제거하고 HTML로 해석하지 않는다. 닉네임은 채점에 영향을 주지 않는다. 모든 문구에 조사 처리가 필요한 구조를 피하고 “{nickname}님은”을 쓴다.

### 질문 화면

상단에 이전 아이콘, “나의 첫 병동”, “03 / 12”. 아래에 진행 바, 작은 캐릭터, 질문, 답변 4개, 하단 다음 버튼 순서로 배치한다. 안내는 “정답은 없어요. 지금 더 끌리는 답 하나를 골라주세요.”로 통일한다. 실무 경험이 없는 학생도 답할 수 있도록 지식 정답형 질문을 사용하지 않는다.

답변을 누르면 선택 상태만 바뀌고 다음 버튼으로 확정한다. 자동으로 다음 문항으로 넘기지 않는다. 선택 상태는 테두리·배경·체크 아이콘을 함께 사용한다. 미선택 시 다음 버튼 비활성화. 마지막 CTA는 “내 결과 보기”. 뒤로 가도 답변 유지, 답변 변경 시 결과 전체 재계산. 선택을 바꿀 때 가산 점수를 누적하지 않는다.

4문항 완료 시 “좋아요, 나만의 스타일이 조금씩 보여요.”, 8문항 완료 시 “이제 네 번의 선택만 남았어요.”를 짧게 표시한다. 답변 내용에 대해 정답·오답 같은 반응은 하지 않는다.

### 결과 공개

마지막 확정 후 600~900ms 동안 명찰이 뒤집히는 연출을 1회 제공한다. 카피는 “선택한 답변으로 명찰을 준비하고 있어요.”. 계산은 즉시 수행하며 가짜 AI 분석·뇌 분석·서버 분석을 표시하지 않는다. 모션 줄이기 설정에서는 즉시 표시한다.

### 결과 페이지 정보 순서

1. “{nickname}님의 병동 취향” + 결과 부서명 + 캐릭터 + 별칭.
2. **개인화 요약 2~3문장**: 실제 답변에서 확인된 취향과 해당 부서의 연결.
3. 태그 3개: 해당 부서의 고정 테마 태그. “당신의 검증된 능력”으로 표기하지 않음.
4. **이 결과가 나온 이유**: 실제 선택 2~3개의 원문/요약과 연결 설명. 기본 펼침.
5. **어떤 병동·부서인가요?**: 대상·대표 업무·업무 흐름. 기본 펼침.
6. “이런 장면에 흥미를 느낄 수 있어요”와 “미리 알아두면 좋아요”. 기본 펼침.
7. 2위 부서: “함께 살펴볼 취향”. 가까운 점수면 별도 문구 노출.
8. “실습 때 이런 걸 관찰해보세요” 1개.
9. “결과 이미지 저장”, “친구에게 공유”, “다시 해보기”.
10. 작은 고지와 참고 자료 펼치기: “이번 선택을 바탕으로 만든 재미용 결과예요. 모든 부서에서 관찰·소통·협업은 중요하며, 실제 경험은 병원과 팀에 따라 달라요.”

결과 페이지는 기사처럼 길게 한 덩어리로 쓰지 말고 2~4문장 단락과 카드 간 여백으로 읽기 쉽게 만든다. “최악의 궁합 병동”이나 “가지 말아야 할 부서”는 제공하지 않는다.

## 3 문항 전문과 채점 데이터

각 문항 4지선다, 모두 단일 선택. 아래 순서와 문구를 초기 버전에서 고정한다. 화면에는 점수와 내부 코드가 보이지 않는다. 문항의 태그는 개인화 이유 생성에 사용한다.

코드: ER 응급실 / ICU 중환자실 / OR 수술실 / MED 내과계 병동 / PED 소아병동 / PSY 정신건강의학과 병동 / ONC 종양병동.

각 답변의 앞 코드는 2점, 뒤 코드는 1점. 예: `ER/ICU`는 ER 2점, ICU 1점. 나머지 부서는 0점이다.

## 4 점수와 개인화 이유 생성 규칙

### 점수 계산

문항은 임상 능력이나 성격 척도를 측정하지 않는다. 질문에 등장하는 활동 선호를 제작자가 부서 테마에 연결한 규칙이다. 선택지 간 관계가 없는 임의의 MBTI 축이나 심리학적 검사명을 붙이지 않는다.

부서마다 선택지 노출 횟수가 다르므로 단순 총점만 비교하지 않는다. 각 부서가 12문항에서 얻을 수 있는 이론상 최대점수로 나눈 정규화 점수를 내부 순위에 사용한다.

```text
raw[d] = 모든 문항에서 선택한 답변의 d 가중치 합
max[d] = 모든 문항별로 d 가중치의 최댓값을 구해 합산
normalized[d] = raw[d] / max[d]
```

가중치는 위 표에서 계산하고 최대점수를 중복 하드코딩하지 않는다. 정규화는 단순한 노출 차이 보정일 뿐 통계적 타당성이나 동등한 당첨 확률을 보장하지 않는다. 외부에는 점수·퍼센트·상위 백분위·희귀도를 표시하지 않는다.

정렬은 normalized 내림차순 → 해당 부서 2점 답변 선택 횟수 내림차순 → 고정 코드 순서 `ER, ICU, OR, MED, PED, PSY, ONC`로 한다. 비율 비교는 가능하면 교차곱으로 수행한다. 동점의 최종 순서는 오직 재현성을 위한 구현 규칙이다.

1위와 2위 normalized 차이가 0.08 이하이면 “두 가지 취향이 비슷하게 나타났어요. {1위}와 {2위}를 함께 살펴보세요.”를 표시한다. 완전 동점이면 “이번 선택에서는 두 유형의 점수가 같았어요.”를 우선 표시하고 공동으로 소개한다. 세 부서 이상 공동 최고점이면 공동 유형 모두 이름을 표시하고 대표 카드는 정렬 규칙에 따라 하나를 보여준다. 0.08은 제작자 설정값이며 연구로 검증된 기준이 아니다.

### 이유 추출

1. 1위 부서에 1점 이상 기여한 실제 선택만 후보로 추린다.
2. 기여도 2점 우선, 그다음 문항 번호 오름차순으로 정렬한다.
3. 서로 다른 취향 태그를 우선 골라 최대 3개 선택한다. 서로 다른 태그가 부족하면 같은 태그의 다른 문항으로 보충한다.
4. 두 후보만 있으면 두 개만 표시한다. 하나면 하나만 표시한다. 0개이면 문항 매핑 오류로 간주하고 일반 결과를 만들지 않는다.
5. 선택 문구 자체와 태그에 대한 설명을 보여준다. 선택하지 않은 근거나 점수 0인 근거를 만들지 않는다.
6. 2위 결과도 설명을 붙일 경우 2위 부서에 기여한 선택만 사용한다.

취향 태그별 설명 템플릿:

| 태그 | 선택에서 읽을 수 있는 취향 |
| --- | --- |
| 우선순위 정리 | 여러 선택지 중 먼저 살펴볼 것을 정리하는 활동에 끌렸어요 |
| 변화 관찰 | 작은 차이를 확인하고 의미를 이해하는 활동에 관심을 보였어요 |
| 경청 | 상대의 걱정과 생각을 충분히 듣는 방식을 골랐어요 |
| 흐름 조율 | 여러 일정과 과정을 연결하는 역할을 선호했어요 |
| 절차 준비 | 필요한 항목과 순서를 미리 갖추는 활동에 끌렸어요 |
| 눈높이 설명 | 상대가 이해하기 쉬운 표현으로 바꾸는 활동을 골랐어요 |
| 꾸준한 동행 | 한 번의 만남 뒤에도 이어지는 과정을 챙기는 데 관심을 보였어요 |
| 상황 전환 | 상황이 바뀔 때 계획과 역할을 조정하는 활동에 끌렸어요 |
| 패턴 탐색 | 기록과 현황을 비교해 연결되는 부분을 찾는 데 관심을 보였어요 |
| 신뢰 형성 | 상대가 편하게 질문하고 이야기하도록 돕는 방식을 골랐어요 |

개별 근거 카드는 `Q번호 + “선택한 답변” + 위 태그 설명`으로 만든다. 전체 요약은 `“{nickname}님은 이번 질문에서 {상위 근거 태그1}와 {다른 근거 태그2}에 가까운 선택을 했어요. 이런 취향을 {부서의 연결 문장}과 연결해, {별칭} 유형으로 소개해드려요.”`로 생성한다. 태그가 하나면 하나만 자연스럽게 사용한다. 모든 문장이 고정 결과 문구인 것처럼 보이지 않도록 최소 2개의 실제 답변을 드러내는 것을 기본 목표로 한다.

LLM API는 사용하지 않는다. 규칙 기반 템플릿으로 재현성과 답변 근거를 보장한다. “위기에서 침착한 능력이 뛰어나요”처럼 취향을 실제 임상 역량으로 확대 해석하지 않는다.

## 5 일곱 가지 결과 콘텐츠

아래 병동 설명은 고정 정보, 개인화 요약과 근거 카드는 선택에 따라 바뀌는 정보다. 각 부서는 업무가 서로 겹칠 수 있으며, 유형의 차이는 다른 부서에 해당 역량이 없다는 뜻이 아니다.

### ER 응급실의 우선순위 나침반

- **명찰 한 줄:** “달라지는 상황 속에서 다음 방향을 찾는 나침반”
- **태그:** #우선순위 #상황전환 #팀소통
- **요약용 연결 문장:** “응급실에서 변화하는 요구를 파악하고 팀과 정보를 공유하는 업무”
- **어떤 부서인가요:** 갑작스러운 질환이나 손상으로 방문한 환자를 평가하고 필요한 처치와 검사, 입원 또는 귀가 과정이 이어지도록 돕는 부서예요. 긴급한 필요를 파악하고 우선순위를 판단하는 과정이 중요해요. 실제 역할은 교육 수준과 병원 체계에 따라 달라요. [R1]
- **흥미를 느낄 장면:** 새로운 상황이 들어올 때 정보를 정리하고, 팀과 공유하며 다음 과정을 연결하는 장면.
- **미리 알아둘 점:** 예측하기 어려운 흐름과 빠른 변화가 있어요. 재미있는 돌발 상황을 좋아하는 것과 실제 응급 상황에 대처할 준비는 별개이며 교육과 경험이 필요해요.
- **실습 관찰 질문:** “팀은 어떤 정보를 먼저 공유하고, 변경된 우선순위를 어떻게 전달할까?”
- **캐릭터 소품:** 작은 나침반 배지와 상황 메모 카드. 뛰거나 영웅처럼 환자를 구하는 과장된 연출 대신 방향을 가리키는 포즈.

### ICU 중환자실의 변화 탐정

- **명찰 한 줄:** “작은 변화를 이어서 큰 흐름을 읽는 탐정”
- **태그:** #변화관찰 #패턴탐색 #집중
- **요약용 연결 문장:** “중환자실에서 환자의 상태 변화를 살피고 팀과 함께 의미를 파악하는 업무”
- **어떤 부서인가요:** 위중한 환자에게 집중적인 관찰과 복합적인 간호를 제공하는 부서예요. 환자 상태, 모니터링 정보와 치료 반응을 함께 살피며 여러 직종과 협력해요. 환자와 가족을 지원하는 소통도 중요해요. [R2, R8]
- **흥미를 느낄 장면:** 작은 상태 변화와 기록을 비교하며 의미를 배우고 팀과 공유하는 장면.
- **미리 알아둘 점:** 숫자나 장비만 다루는 곳은 아니에요. 급격한 변화에 대응하는 교육, 여러 정보를 함께 보는 연습과 가족 소통이 필요해요.
- **실습 관찰 질문:** “모니터 정보와 직접 관찰한 환자 상태를 어떻게 함께 해석할까?”
- **캐릭터 소품:** 추세가 그려진 보드와 확대경 모양 배지. 환자 데이터는 가상의 추상 선으로 표현.

### OR 수술실의 준비 지휘자

- **명찰 한 줄:** “필요한 순간을 위해 순서와 준비를 맞추는 지휘자”
- **태그:** #절차준비 #협업 #도구관심
- **요약용 연결 문장:** “수술실에서 준비와 안전 확인, 팀의 순서를 맞추는 업무”
- **어떤 부서인가요:** 수술이 안전하게 진행되도록 환자 간호와 수술 준비를 담당하는 부서예요. 기구와 물품을 준비·관리하는 역할, 수술실 안의 간호와 환경을 조정하는 역할 등이 협력해요. 구체적인 역할 구분은 기관마다 달라요. [R3]
- **흥미를 느낄 장면:** 다음 단계에 필요한 준비를 예상하고 팀의 흐름에 맞춰 움직이는 장면.
- **미리 알아둘 점:** 계획된 수술에도 변화가 생길 수 있어요. 절차 준수뿐 아니라 의사소통, 집중 유지와 신체적 부담에 대한 이해도 필요해요.
- **실습 관찰 질문:** “각자의 준비가 다른 팀원의 다음 행동과 어떻게 이어질까?”
- **캐릭터 소품:** 수술모와 체크리스트. 실제 수술 장면이나 날카로운 기구를 강조하지 않음.

### MED 내과계 병동의 연결 코디네이터

- **명찰 한 줄:** “여러 갈래의 하루를 하나로 이어주는 코디네이터”
- **태그:** #흐름조율 #넓은관심 #연결
- **요약용 연결 문장:** “내과계 병동에서 여러 간호 요구와 검사·치료·교육 과정을 연결하는 업무”
- **어떤 병동인가요:** 다양한 내과적 질환의 입원 환자를 돌보며 상태 관찰, 투약, 검사 준비와 환자 교육 등을 수행하는 병동이에요. 여러 환자의 요구와 치료 일정을 살피며 팀과 조율하는 장면이 많아요. 세부 진료과에 따라 일과는 달라져요. [R4, R8]
- **흥미를 느낄 장면:** 흩어진 요청과 일정을 연결하고 환자의 다음 과정을 준비하는 장면.
- **미리 알아둘 점:** 단순하거나 쉬운 병동이라는 뜻은 아니에요. 다양한 질환과 급격한 상태 변화, 여러 업무의 우선순위를 함께 배우게 돼요.
- **실습 관찰 질문:** “검사·투약·교육 일정이 겹칠 때 팀은 어떻게 조율할까?”
- **캐릭터 소품:** 탭이 달린 일정 보드와 연결 고리 배지.

### PED 소아병동의 눈높이 통역가

- **명찰 한 줄:** “낯선 이야기를 이해할 수 있는 말로 바꾸는 통역가”
- **태그:** #눈높이설명 #가족소통 #표현의유연함
- **요약용 연결 문장:** “소아병동에서 아동의 발달과 이해 수준을 고려하고 가족과 소통하는 업무”
- **어떤 병동인가요:** 아동의 발달 단계와 건강 상태를 고려해 간호하고 보호자와 함께 돌봄을 이어가는 병동이에요. 아이의 표현을 살피고 이해할 수 있는 방법으로 설명하며 가족의 궁금증을 함께 다뤄요. [R5]
- **흥미를 느낄 장면:** 그림이나 비유, 놀이 요소를 활용해 낯선 설명을 이해하기 쉽게 전달하는 장면.
- **미리 알아둘 점:** 아이를 좋아하는 마음만으로 결정되는 부서는 아니에요. 연령별 차이와 안전한 간호를 배우고, 아동과 보호자의 서로 다른 요구도 살펴야 해요.
- **실습 관찰 질문:** “같은 설명도 아동의 나이와 보호자의 궁금증에 따라 어떻게 달라질까?”
- **캐릭터 소품:** 곰 인형과 그림 설명 카드. 아이 같은 간호사가 아니라 성인 간호사의 귀여운 캐릭터화.

### PSY 정신건강의학과 병동의 대화 동행자

- **명찰 한 줄:** “말과 표정 사이에서 함께 걸을 속도를 찾는 동행자”
- **태그:** #경청 #신뢰형성 #차분한소통
- **요약용 연결 문장:** “정신건강의학과 병동에서 신뢰를 쌓으며 환자의 상태와 요구를 살피는 업무”
- **어떤 병동인가요:** 정신건강 문제를 겪는 환자의 상태를 살피고 치료와 일상 회복을 지원하는 병동이에요. 치료적 의사소통과 교육, 안전한 환경 유지, 팀 기반의 간호가 함께 이뤄져요. 단순 상담만 하는 부서는 아니에요. [R6]
- **흥미를 느낄 장면:** 상대의 말을 듣고 질문 방식을 조절하면서 신뢰를 쌓는 장면.
- **미리 알아둘 점:** 경청뿐 아니라 전문적인 관계의 경계, 안전과 상태 변화에 대한 교육도 중요해요. 개인적인 친밀함과 치료적 관계를 동일하게 보지 않아요.
- **실습 관찰 질문:** “공감하면서도 전문적인 관계의 경계를 어떻게 유지할까?”
- **캐릭터 소품:** 서로 마주 보는 말풍선과 작은 의자. 환자나 정신질환을 희화화하지 않음.

### ONC 종양병동의 여정 메이트

- **명찰 한 줄:** “한 번의 만남 너머 다음 과정까지 함께 보는 메이트”
- **태그:** #꾸준한동행 #과정이해 #교육과지원
- **요약용 연결 문장:** “종양병동에서 치료 과정에 맞춰 교육과 증상 관리, 환자·가족 지원을 이어가는 업무”
- **어떤 병동인가요:** 암 환자의 치료와 회복 과정에서 상태를 살피고 치료 관련 증상 관리, 교육과 정서적 지원을 제공하는 병동이에요. 치료 과정과 환자의 요구에 맞춰 여러 직종과 협력해요. 모든 환자가 같은 치료 경로나 입원 기간을 갖는 것은 아니에요. [R7]
- **흥미를 느낄 장면:** 치료 단계가 바뀔 때 필요한 설명과 지원을 함께 준비하는 장면.
- **미리 알아둘 점:** 따뜻한 동행과 함께 치료 안전과 복잡한 증상에 대한 학습이 중요해요. 어려운 감정을 혼자 감당하는 희생형 이미지로 받아들이지 않도록 해요.
- **실습 관찰 질문:** “치료 단계가 달라질 때 교육 내용과 지원 방식은 어떻게 바뀔까?”
- **캐릭터 소품:** 이어지는 길이 그려진 작은 지도와 새싹 배지. 완치나 특정 경과를 약속하는 상징은 피함.

## 6 실제 결과 화면 예시

아래는 Q1 B, Q3 B, Q6 A 등을 포함해 ICU가 1위인 답변 조합을 가정한 예시다. 실제 앱에서는 해당 답변을 선택했을 때만 각 근거를 사용한다.

**종희님의 병동 취향은 중환자실의 변화 탐정**

“종희님은 이번 질문에서 작은 변화를 확인하고 기록의 패턴을 찾아보는 활동에 가까운 선택을 했어요. 이런 취향을 중환자실에서 환자의 상태 변화를 살피고 팀과 함께 의미를 파악하는 업무와 연결해, ‘변화 탐정’ 유형으로 소개해드려요.”

**이 결과가 나온 이유**

- Q1에서 “예약과 이동 정보를 비교하며 바뀐 부분부터 확인해요”를 골랐어요. 작은 차이를 확인하고 의미를 이해하는 활동에 관심을 보였어요.
- Q3에서 “작은 기록을 비교해 전체 패턴을 찾아내는 것”을 골랐어요. 기록과 현황을 비교해 연결되는 부분을 찾는 데 관심을 보였어요.
- Q6에서 “작은 차이를 발견하고 그 의미를 이해했을 때”를 골랐어요. 변화를 발견하는 과정 자체에 끌리는 답변이었어요.

이후 위 ICU의 병동 소개·흥미 장면·미리 알아둘 점·실습 관찰 질문을 이어 붙인다. “종희님은 이미 중환자실에 적합한 능력을 갖췄다”는 단정은 하지 않는다.

## 7 캐릭터와 화면 디자인 명세

### 아트 방향

전체 분위기는 **간호사 캐릭터가 안내하는 작은 병동 탐험 노트**. 민트와 크림 배경에 둥근 의료 소품을 사용하고, 캐릭터의 존재감이 첫인상을 결정하도록 한다. 의료 대시보드, 딱딱한 병원 홈페이지, 스톡 사진 중심 레이아웃은 이 기획의 방향과 맞지 않는다.

캐릭터는 하나의 기본 인물을 유지하고 결과별 소품과 자세만 바꾼다. 2.5등신, 둥근 실루엣, 짧거나 단정히 정리한 머리, 중성적인 외형, 스크럽과 운동화, 큰 명찰을 사용한다. 특정 성별·체형이 특정 부서에 어울린다는 인상을 만들지 않는다. 표현은 따뜻한 2D 벡터 일러스트 또는 일관된 소프트 셰이딩으로 통일한다.

필요 자산: 기본 캐릭터 1종, 질문용 상반신 1종, 결과별 7포즈, 민트 병원 배경 1종, 체크리스트·펜·반창고·하트·말풍선 등의 장식 소품 6종. 파일명은 `nurse-hero`, `nurse-question`, `nurse-er` 등으로 통일한다. 글자는 이미지에 넣지 말고 HTML로 렌더링한다. 실제 병원 로고나 기존 캐릭터를 복제하지 않는다.

구현 단계에서 그림 자산이 없으면 같은 비율·색상·선 굵기를 공유하는 오리지널 SVG 캐릭터 컴포넌트를 제작한다. 이모지 하나나 아이콘 하나를 메인 캐릭터로 대체하지 않는다. 생성형 이미지 도구 사용 가능 시 이 방향으로 일관된 캐릭터 자산을 만들 수 있지만, 외부 API가 없다고 핵심 흐름 구현을 멈추지 않는다.

### 반응형 배치

| 화면 너비 | 레이아웃 |
| --- | --- |
| 320~359px | 좌우 16px, 캐릭터 높이 180~210px, 제목 30px, 자연스러운 세로 스크롤 |
| 360~479px | 좌우 20px, 캐릭터 높이 220~270px, 질문 및 답변 단일 열 |
| 480~767px | 앱 최대 너비 480px, 중앙 정렬 |
| 768~1023px | 앱 최대 너비 560px, 주변 배경 여백 확대 |
| 1024px 이상 | 전체 최대 1040px. 왼쪽 캐릭터 소개 400px, 오른쪽 테스트 480px. 결과는 최대 760px 중앙 단일 열 |

첫 화면에서 제목과 캐릭터·시작 버튼이 우선 보이도록 구성하되, 작은 화면에서 한 화면에 억지로 끼워 넣지 않는다. 캐릭터는 큰 중앙 이미지이며 텍스트 뒤에 겹치지 않는다. 병원 배경 장식은 저대비·비상호작용·`aria-hidden` 처리한다.

선택지는 높이 최소 64px, 간격 12px. 조작 버튼은 최소 48×48px로 설계한다. 하단 다음 버튼은 `position: sticky`를 사용하고 실제 높이만큼 콘텐츠 공간을 확보한다. `env(safe-area-inset-bottom)`을 반영한다. 이름 입력 중 키보드가 올라오면 고정 CTA가 입력을 가리지 않도록 일반 흐름으로 전환한다. 높이는 고정 `100vh` 대신 자연 흐름과 `min-height:100dvh`를 사용한다.

### 접근성과 모션

실제 radio input과 label, fieldset/legend를 사용한다. 방향키로 선택, Tab으로 이동, Enter/Space로 버튼 실행이 가능해야 한다. 다음 문항으로 이동하면 질문 제목에 초점을 옮긴다. 진행 수치는 스크린리더에 제공하고 장식 캐릭터는 읽지 않도록 한다. 상태 변경 알림은 짧은 `aria-live=polite` 영역을 사용한다. 확대 200%에서 텍스트와 버튼이 겹치지 않아야 한다. 모션은 150~250ms, 히어로 등장과 결과 공개 정도로 제한하며 `prefers-reduced-motion`을 따른다. [R9, R10]

## 8 저장과 공유

기본 공유 카드는 1080×1350 PNG. 캐릭터, 별칭, 부서명, 테마 태그 3개, “나의 첫 병동”, 서비스 주소와 “재미용 취향 테스트”를 넣는다. 개인화 이유 전체와 응답 원문은 공유 이미지에 넣지 않는다. 이미지 저장 미리보기에서 “닉네임 포함” 토글을 제공하고 기본은 꺼짐으로 한다.

공유 URL은 `/#/result/ICU?v=1` 같은 부서 코드와 콘텐츠 버전만 포함한다. 닉네임·원응답·세부 점수는 URL에 넣지 않는다. 공유 링크로 들어온 사용자는 **“친구가 공유한 중환자실 유형”**이라는 일반 부서 소개를 보고 “나도 테스트하기”로 이동한다. 원응답이 없으므로 개인화 이유나 “당신은” 문구를 보여주지 않는다. 자신의 결과 화면과 공유용 일반 결과 화면을 구분한다.

Web Share API를 지원하면 사용자 클릭에서 네이티브 공유창을 연다. 파일 공유는 `navigator.canShare({files})`로 별도 확인한다. 공유 취소는 오류 알림으로 처리하지 않는다. 미지원·실패 시 URL 복사 버튼과 선택 가능한 URL 텍스트를 제공한다. PNG 저장 실패 시 이미지 미리보기와 “길게 눌러 저장” 대안을 제공한다. [R11]

카카오 전용 SDK는 MVP 필수가 아니다. 카카오톡 인앱 브라우저에서는 직접 동작을 점검한다. 서버 없는 SPA의 해시별 OG 미리보기는 구분되지 않으므로 기본 서비스 OG 이미지와 제목을 사용한다. 결과별 OG가 필요하면 후속 범위에서 정적 결과 경로나 서버 렌더링을 추가한다.

## 9 구현 계약

새 프로젝트라면 React + TypeScript + Vite를 기본안으로 한다. 기존 프로젝트가 있으면 해당 구조와 패키지 관리자를 우선한다. CSS는 CSS Modules 또는 프로젝트 기존 방식으로 통일한다. 결과 이미지 렌더러는 필요한 시점에 동적 로딩한다. 버전을 이 PRD에서 고정하지 말고 구현 시 호환되는 안정 버전과 lockfile을 확정한다.

데이터와 계산을 UI에서 분리한다:

```text
src/data/questions.ts        문항 12개와 가중치·태그
src/data/wards.ts            결과 7개와 설명·캐릭터·출처
src/lib/scoring.ts           점수 계산과 동점 처리
src/lib/explanation.ts       실제 선택에 기반한 이유 추출
src/lib/storage.ts           저장과 복구·버전 검증
src/lib/share.ts             URL 공유와 PNG 저장
src/components/NurseCharacter.tsx
src/screens/IntroScreen.tsx
src/screens/QuestionScreen.tsx
src/screens/ResultScreen.tsx
src/screens/SharedResultScreen.tsx
```

```ts
type WardId = 'ER'|'ICU'|'OR'|'MED'|'PED'|'PSY'|'ONC';
type Choice = {
  id: 'A'|'B'|'C'|'D';
  text: string;
  tag: string;
  weights: Partial<Record<WardId, 1|2>>;
};
type Question = { id: number; text: string; choices: Choice[] };
type QuizState = {
  schemaVersion: 1;
  contentVersion: '1.0';
  nickname: string;
  answers: Record<number, Choice['id']>;
  currentQuestion: number;
  phase: 'intro'|'quiz'|'result';
  updatedAt: number;
};
```

`Ward` 데이터에는 ID, 부서명, 별칭, 태그, 요약용 연결 문장, 부서 소개, 흥미 장면, 미리 알아둘 점, 실습 관찰 질문, 이미지 키, 참고 자료 ID를 포함한다.

상태는 `intro → quiz → result`로 전환하며 공개 연출은 전환 애니메이션으로 처리한다. 모든 응답이 유효할 때만 결과 화면을 연다. 직접 잘못된 결과 URL을 열면 “결과를 찾을 수 없어요”와 시작 CTA를 제공한다.

로컬 저장 키는 `first-ward:quiz:v1`. 각 응답 변경 시 저장하고 새로고침 시 “이어서 하기 / 새로 시작하기”를 제공한다. 7일 지난 저장은 폐기하며 schema/contentVersion 불일치와 손상 데이터는 안전하게 초기화한다. 저장을 차단한 브라우저는 메모리 상태로 진행하고 “이 브라우저에서는 새로고침하면 답변이 사라질 수 있어요”를 짧게 안내한다. 다시하기는 응답과 결과를 초기화하고 닉네임은 유지할 수 있다. “내 기록 지우기”는 닉네임을 포함한 저장 전체를 지운다.

브라우저 뒤로 가기는 질문 간 이동을 지원하고, 새로고침 복구와 충돌하지 않도록 답변 상태를 단일 저장소로 관리한다. 공유 결과 페이지에서 시작하면 저장된 본인 결과를 덮어쓰기 전에 이어하기 또는 새로하기를 고르게 한다.

MVP에는 외부 분석 SDK를 기본 설치하지 않는다. 네트워크로 닉네임이나 응답을 전송하지 않는다. 후속 분석이 필요하면 이름·답변 없이 `test_start`, `question_complete(questionId)`, `result_view(wardId)`, `share_click`, `save_success` 정도의 이벤트를 설계한다. 공유 클릭 수를 실제 공유 완료 수로 표현하지 않는다. 초기 완주율 70%, 완료 시간 중앙값 3분 이내는 운영 목표 가설이며 검증된 성과가 아니다.

## 10 QA와 출시 조건

- 12문항 × 4선택지의 문구·태그·가중치가 모두 데이터에 존재한다.
- 모든 부서의 최대점수가 0보다 크고, 7종 결과 모두 도달 가능한 답변 조합을 확보한다.
- 같은 응답의 결과·순위·이유가 매번 동일하다. 이전 답변 수정 후 누적 오류가 없다.
- 고정 시드의 균등 임의 응답 시뮬레이션으로 구조적 편중을 확인한다. 실제 사용자 분포나 적합도로 홍보하지 않는다. 편중이 보이면 문항 노출과 가중치를 검토하되 균등한 결과 수를 맞추려고 근거를 왜곡하지 않는다.
- 동점, 근접점수, 하나의 태그만 반복된 경우, 일부 응답 유실을 점검한다.
- 설명의 모든 Q번호와 인용이 실제 선택과 일치하고 해당 부서에 점수를 준 답변이다.
- 닉네임 없는 경우·긴 한글·이모지·HTML처럼 보이는 입력에서 화면과 저장이 안전하다.
- 320, 360, 390, 430, 768, 1440px에서 가로 스크롤·잘림·CTA 겹침이 없다.
- iOS Safari, Android Chrome, 카카오톡 인앱에서 결과 저장과 공유 대안을 확인한다. 실제 기기 검증을 못 했다면 완료 보고서에 미검증으로 명시한다.
- 새로고침, 저장 차단, 손상 저장, 유효하지 않은 공유 URL, 브라우저 뒤로 가기를 점검한다.
- 키보드와 스크린리더로 문항 진행 가능. 텍스트 대비와 200% 확대 확인.
- 캐릭터·글꼴을 자체 제공하고 공유 이미지 캡처 전 폰트/이미지 로딩을 기다린다. 외부 이미지의 CORS 문제로 PNG 저장이 실패하지 않는다.
- 네트워크 오류가 없어도 불필요하게 기다리는 분석 화면이나 허구의 이용자 수를 만들지 않는다.
- 출시 전 간호학생·신규 간호사 소규모 사용자에게 문항 이해도와 결과 이유의 납득도를 확인한다. 현직 간호사에게 부서 소개의 오해 소지를 검토받는 것을 권장한다. 이 검토를 심리검사 검증이라고 부르지 않는다.

### PRD 단계에서 확인한 채점 구조

12문항·48선택지를 문서에서 추출해 고정 시드 17로 균등 임의 응답 50,000개를 계산했다. 7개 결과가 모두 도달 가능했다. 결과 수는 ER 7,682 / ICU 6,461 / OR 5,775 / MED 7,074 / PED 7,366 / PSY 7,006 / ONC 8,636이었다. 이는 규칙의 구조 확인이며 사용자 조사·심리 타당도·실제 사이트 테스트가 아니다. 최대점수는 ER 16 / ICU 19 / OR 18 / MED 19 / PED 17 / PSY 18 / ONC 19였다.

구현 테스트에 사용할 1위 결과 예시 답변은 Q1~Q12 순서로 ER `ACBBCCBBCDCD`, ICU `CDBABBBBCAAC`, OR `AACADCDABCCA`, MED `DCCCBCAABDDC`, PED `ABBBBDCDBCBD`, PSY `CBBCCCCBCACC`, ONC `DADBDCADCACA`다.

## 11 Claude Code에 전달할 실행 지시

이 PRD를 기준으로 한국어 모바일 우선 반응형 웹앱을 구현하라. 먼저 프로젝트 구조를 확인하고, 문항·채점·결과 설명을 데이터로 분리한 후 화면을 구현하라. 12개 문항과 7개 결과를 생략하거나 임의의 MBTI 매칭으로 바꾸지 마라. 첫 화면의 큰 간호사 캐릭터와 결과별 일관된 캐릭터 변형을 반드시 구현하라. 가장 중요한 기능은 실제 선택에 근거한 개인화 요약과 이유 설명이다. 시작, 질문, 결과, 공유 결과까지 모두 작동하게 하고 저장·복구·이미지 저장·공유 대안을 완성하라. 구현 후 채점과 근거 일치 테스트, 모바일 화면 점검을 수행하고 실행 방법과 미검증 항목을 짧게 보고하라. 외부 배포는 별도 요청이 있을 때 진행하라.
